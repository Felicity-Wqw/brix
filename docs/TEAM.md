> 项目：物归校园（Brix Campus Market）· 校园二手交易平台
> 小组：5 人 · 周期：6 周（含联调、测试、文档与答辩准备）
> 技术栈：Spring Boot 3.5 + MyBatis-Plus + MySQL 8 / Vue 3 + TypeScript + Vite + Element Plus / LangChain4j（DeepSeek）

## 二、逐人职责明细

### 赵容溥 · 前端开发（25%）

**职责范围**

1. **工程搭建**：Vite 7 + Vue 3 + TypeScript 项目骨架，路由、Pinia 状态、Axios 封装（统一 `R` 解包、错误码处理、401 跳转带回跳）
2. **页面开发（38 个 SFC）**：
   - 首页：Hero 校园实景轮播、分类图标卡 + 二级胶囊筛选（Apple 风）、商品瀑布流、分页
   - 商品：详情页（图集、卖家名片、同类好物、留言区）、发布页（级联分类、品牌快捷标签、图片上传、AI 估填）
   - 交易：下单弹窗（面交时间/邮寄收货三件套动态表单）、收银台（**微信/支付宝双支付沙箱拟真弹窗**）、订单列表/详情、评价
   - 互动：私信聊天（**iMessage 风**：日期分隔、无边框气泡、圆形发送键）、留言、收藏、浏览历史
   - 账号：登录页（**微信扫码登录沙箱**、游客模式入口）、注册、个人中心、数据可视化（ECharts）
3. **设计语言落地**：温暖纸感校园市集风格（暖纸底 + 墨绿主色 + 价签橙红）、**毛玻璃导航/页脚/商品卡下半区**、响应式适配 1280px+
4. **联调与前端自测**：12 个 api 模块对接，WebSocket 客户端（自动重连、消息去重）

**产出物**：`frontend/` 全量代码 · 设计令牌（styles/tokens.css）· 组件库复用说明

**协作接口**：与后端约定 `R` 结构与字段命名；与 AI 成员约定估价/文案出参；向测试提交可运行版本与已知问题清单

### 连斌 · 后端开发（25%）

**职责范围**

1. **架构与基础设施**：Spring Boot 分层（common/config/controller/service/mapper/model/enums）、统一响应体 `R`、全局异常处理、Jackson 全局配置（`Long` 转字符串、日期格式 `yyyy-MM-dd HH:mm:ss`）、Druid 连接池
2. **数据库设计（12 张表）**：`t_user / t_category / t_item / t_item_image / t_order / t_review / t_favorite / t_browse_history / t_item_comment / t_chat_message / t_report / t_ai_estimate_log`，索引与逻辑删除规范
3. **11 个控制器 / 42 个接口**：
   - 认证（JWT + BCrypt）、用户资料、分类
   - 商品 CRUD + 上下架 + 同类推荐 + 浏览埋点
   - **订单核心**：下单（面交/邮寄交叉校验）→ 支付（**条件更新 CAS 防超卖**）→ 发货 → 确认收货（**同事务写 `settle_time` 释放托管**）→ 取消/超时关单
   - 留言（未读体系）、收藏（幂等切换）、举报、文件上传
4. **专项**：WebSocket 私信推送、待付款 30 分钟超时关单定时任务、留言未读红点接口

**产出物**：`backend/` 全量代码 · `db/schema.sql` · 接口文档初稿

**协作接口**：与前端每日同步接口变更；给 AI 成员提供工具查询的 Mapper 方法；给测试提供 Postman/脚本集合

---

### 王虔伟 · AI 服务（20%）

**职责范围**

1. **智能体装配**：LangChain4j + DeepSeek（`ObjectProvider` 可选装配，无 Key 自动降级规则引擎，系统不崩）
2. **估价智能体（核心亮点）**：
   - **两阶段定价**：无原价时先用 LLM 知识库估新品价作第二锚点 → 与成交库数据综合定价
   - **工具集**：`soldPriceStats`（成交统计 + **成交样本标题回传**）、`onSaleLowestPrice`、`conditionDiscountFactor`
   - **同款判定三层防线**：工具关键词收紧（禁止品牌名凑数据）→ 提示词同款核对规则 → `AiResultSanitizer` **原价硬钳制**（二手价 ≤ 原价×0.98）
3. **文案智能体**：分类驱动的三段式挂牌简介（亮点/成色瑕疵/交易说明）+ 合规红线过滤
4. **审核智能体**：发布合规第二道闸，四选一判定（通过/驳回下架/修改重审/上报风控），**AI 只能拒绝不能阻断**
5. **工程化**：每日额度（10 次）、调用日志（`t_ai_estimate_log`）、结果清洗与兜底、提示词版本管理

**产出物**：`ai/` 包（12 个类）· 提示词库（AiPrompts）· 降级策略说明 · 估价效果对比样例

**协作接口**：与后端约定 DTO/VO 契约；给前端提供 `source` 字段区分 LLM/规则结果；给测试提供无 Key 降级验证方法

### 黄亚彬 · 测试（15%）

**职责范围**

1. **测试用例设计**：按模块编写用例（认证/商品/订单/留言/私信/AI），覆盖正向、边界、异常
2. **接口测试**：Postman 集合 + 脚本化回归（登录 → 发布 → 下单 → 支付 → 发货 → 收货 → 评价 全链路）
3. **专项测试**：
   - **并发抢单**：两账号同时对同一商品支付，验证只有一个成功、另一个提示「已被抢先购买」
   - **越权**：非卖家改商品、非买家支付订单、非本人删留言 → 403
   - **状态机**：非法流转（已完成后再次支付、未发货直接确认收货）全部被拒
   - **超时关单**：待付款超 30 分钟自动取消，商品回到在售
   - **资金链路**：托管 → 确认收货 → `settle_time` 写入、`escrowDesc` 文案正确
   - **AI 降级**：清空 Key 后估价走规则引擎、发布审核仅词表闸，系统不报错
   - **前端走查**：多分辨率（1280/1440/1920）、游客模式拦截、支付沙箱流程、移动端折叠
4. **缺陷管理**：缺陷记录（复现步骤/严重级别/归属）→ 回归验证 → 关闭
5. **验收清单**：答辩前全功能回归，输出《测试报告》

**产出物**：测试用例表 · 缺陷清单 · 全链路回归脚本 · 《测试报告》

**协作接口**：缺陷直接指派到对应开发；每日站会同步阻塞项

### 王桂南 · 数据汇总（15%）

**职责范围**

1. **种子数据体系（`db/data.sql` 422 行 + `seed-transactions.sql` 155 行）**：
   - 演示账号（student01 / seller01~05 / reviewer01 / operator01）、8 大类 40 小类分类树
   - 商品（含成色/交易方式/校区/品牌）、订单（各状态覆盖）、留言、收藏、浏览、评价
   - **90 天成交记录**（供 AI 估价参考的真实数据源）
2. **内容与素材**：
   - 商品**真实主题图**（13 张分类图，手机/平板/耳机/笔记本/显示器/图书/运动/家居），按标题关键词映射 100+ 商品
   - 15 件商品的**详细描述**（购入渠道/使用时长/配件/瑕疵/交易说明，可信的二手文案）
   - 34 条**对话式评论**（买家提问 + 卖家专业回复）
3. **数据校验**：各表行数一致性、分类挂载完整性、图片路径可达性、金额与状态匹配
4. **文档统筹**：`README.md`、`docs/STARTUP.md`（启动指南）、`docs/DESIGN.md`（架构/功能结构/E-R/状态机/时序）、`docs/API.md`（42 接口）、`docs/diagrams/`（4 张答辩图 SVG+PNG）、FAQ
5. **答辩材料**：PPT 内容组织、演示动线设计、数据看板截图、预答辩跑通

**产出物**：全部 SQL 种子数据 · 商品图片与文案 · 4 份文档
